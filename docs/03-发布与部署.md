# 《解物》发布与部署（四卷 MVP）

> 对应里程碑 M4 → M8。目标：**双击即玩仍然成立**，同时具备 PWA 安装、离线开局、社交分享卡片与静态托管能力。
> 发布物零依赖；源码经 `src/build.py` 内联成 `dist/index.html`，`dist/` 即站点根目录。

---

## 1. 发布物清单

| 文件 | 作用 | 是否必需 |
|---|---|---|
| `dist/index.html` | 游戏本体（四卷；HTML/CSS/JS/SVG 全内联） | 必需 |
| `dist/manifest.webmanifest` | PWA 名称、图标、主题色、启动方式 | PWA 必需 |
| `dist/sw.js` | 离线缓存、导航网络优先、静态资源后台更新 | PWA 必需 |

| `dist/icons/og-card.png` | Open Graph / Twitter 分享底图，1200×630 | 建议 |

`file://` 模式下清单里的后四项不影响运行；`sw.js` 不会注册。根目录的 `index.html` 是冻结的 v0.5 回归基线，不再随构建更新。

## 2. 本地运行

### 2.1 双击即玩（始终保留）

直接双击 `dist/index.html`。无需服务器、无需联网。此模式没有 Service Worker，但四卷玩法、存档、分享卡片生成均可用。

### 2.2 本地预览 PWA

Service Worker 只在 `https://` 或 `localhost` 生效。先构建，再以 `dist/` 为站点根目录启动静态服务器：

```powershell
python src/build.py
cd dist
python -m http.server 8080
```

打开 `http://localhost:8080/`。首次打开后，说明弹层底部会显示「离线缓存已就绪」；此时断网刷新仍可进入。

> 不要用 `file://` 验收离线缓存——浏览器不允许该协议注册 Service Worker，这是有意保留的降级路径。

## 3. 静态托管

源码需要一步构建，但构建只用 Python 标准库。把 `dist/` 的内容原样上传即可，发布目录填 `dist`。

### 3.1 GitHub Pages

1. 运行 `python src/build.py`，把 `dist/` 的内容推到 `gh-pages` 分支根目录。
2. Settings → Pages → Deploy from a branch → `gh-pages` / `/ (root)`。
3. 访问 `https://<user>.github.io/<repo>/`。

相对路径、Manifest 的 `scope: "./"` 与 `sw.js` 的缓存路径都以子目录为基准，放在仓库子路径下也能正常工作。

### 3.2 Netlify

- Build command：留空（本地先运行 `python src/build.py`）
- Publish directory：`dist`

或直接把 `dist/` 拖进 Netlify Drop。

### 3.3 Cloudflare Pages

- Framework preset：None
- Build command：留空（本地先运行 `python src/build.py`）
- Build output directory：`dist`

### 3.4 推荐响应头

单文件应用不需要复杂配置；关键是让入口与 Service Worker 不被长时间缓存：

```text
/sw.js          Cache-Control: no-cache
/index.html     Cache-Control: no-cache
/manifest.webmanifest  Cache-Control: no-cache
/icons/*        Cache-Control: public, max-age=31536000, immutable
```

`sw.js` 自身若被 CDN 长缓存，新版本可能迟迟不生效。发布平台若支持自定义响应头，请优先设置 `/sw.js` 为 `no-cache`。

## 4. PWA 与离线策略

### 4.1 安装条件

- 通过 HTTPS（或 localhost）访问
- 存在 `manifest.webmanifest`，含 192 与 512 图标
- 存在带 `fetch` 处理器的 Service Worker
- 同一 origin 下 `start_url` 可访问

满足后，桌面 Chrome / Edge 地址栏会出现安装入口；Android Chrome 会提示「添加到主屏幕」；iOS Safari 通过「分享 → 添加到主屏幕」安装。游戏内「说明 → 带走这盏灯」会显示当前离线状态，并在浏览器允许时提供「安装到桌面」按钮。

### 4.2 缓存策略

| 请求 | 策略 | 理由 |
|---|---|---|
| 页面导航 | 网络优先，2.5 秒超时回退缓存 | 在线拿最新版，弱网/断网也能进 |
| 图标、Manifest、OG 图 | 缓存优先，后台更新 | 体积小，离线必须可用 |
| 跨域请求 | 不拦截 | 本站没有外部依赖 |

预缓存清单在 `sw.js` 的 `ASSETS` 中。新增发布资源时，必须同步加入清单。

### 4.3 版本更新

1. 提升版本号；构建时 `src/build.py` 会把 `sw.js` 的 `VERSION` 统一写成 `jiewu-v0.8.0-dev`（升级时两处一起改）。
2. 部署。
3. 旧页面下次打开时，新 Worker 安装并 `skipWaiting`；激活阶段删除旧版本缓存。
4. 已受控页面会提示「新版本已备好，下次打开生效」。

更新采用「整包替换 + 删旧缓存」，不保留跨版本状态；游戏存档在 `localStorage`，与缓存版本无关。

### 4.4 回退

若新版本出现问题：

1. 回退 `dist/index.html`、`dist/sw.js`、`dist/manifest.webmanifest` 与 `dist/icons/` 到上一版；
2. 把 `VERSION` 改为一个新的值（不能复用旧值，否则旧缓存可能命中）；
3. 重新部署。

离线用户在下一次联网打开时完成回退。

## 5. 分享卡片与社交元信息

### 5.1 游戏内分享

任意一局结算后点「分享卡片」：

- 用 Canvas 现画 1200×630 分享图（关卡、星级、步数、最优步数、用时、判词、朱砂印）；
- 弹层内可预览、保存 PNG、复制配文；
- 支持 Web Share Level 2 的浏览器（Android Chrome、iOS Safari 等）会多出「系统分享」，可直接把图片分享到其他应用；
- 不支持文件分享的桌面浏览器自动降级为下载图片 + 复制配文。

分享图完全在本地生成，不请求服务器，断网也能用。

### 5.2 链接预览

`dist/index.html` 已写入 Open Graph 与 Twitter Card 元信息，底图为 `icons/og-card.png`。当前使用相对路径，便于本地与任意子目录托管。

正式上线后，建议把以下两处改为**绝对地址**，部分社交平台抓取器不接受相对路径：

```html
<meta property="og:image" content="https://你的域名/icons/og-card.png">
<meta name="twitter:image" content="https://你的域名/icons/og-card.png">
```

并用平台调试工具刷新缓存（例如 Facebook Sharing Debugger、X Card Validator）。

## 6. 小游戏包（后续）

本次 M4 交付的是 H5 / PWA 包，不包含微信小游戏工程。移植路径已在架构上预留：

1. 数学内核（`gray2bin` / `bin2gray` / `canMove` / `nextState`）与渲染层分离，可直接复制；
2. 微信小游戏无 DOM/SVG，需要把 `buildBoard` / `place` / `syncVisual` 改写为 Canvas 2D；
3. 音频从 Web Audio 改为小游戏音频 API，或保留静音降级；
4. 存档从 `localStorage` 改为 `wx.setStorageSync`；
5. 分享卡片改为 `wx.shareAppMessage` + 离屏 Canvas 生成。

现有 H5 版本继续作为网页版与真机回归基线，不以小游戏移植破坏 `file://` 直开能力。
