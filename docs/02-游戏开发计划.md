# 《解连环》游戏开发计划

> 一款以中国古典益智玩具「九连环」为核心的单人解谜游戏。
> 本文是立项文档：定位、玩法、内容、美术、技术、里程碑与风险。
> 配套：`docs/01-资料汇编.md`（考据底稿）、`docs/03-发布与部署.md`（M4 发布手册）、`index.html`（可玩原型 v0.5）。

---

## 0. 一句话

**把 341 步的机械重复，变成一段看得见、听得懂、记得住的旅程。**

九连环的解法一旦知道就毫无难度，难点在「发现规律」和「不走回头路」。因此本作不打算做一个「电子版玩具」，而是围绕这两件事重新设计体验：**前期教你发现递归，中期逼你守住节奏，后期用非标准初态让你真正思考。**

---

## 1. 定位

| 项 | 结论 |
|---|---|
| 类型 | 单人 · 解谜 · 益智 · 文化科普 |
| 平台 | **H5 优先**（桌面 + 移动浏览器，双击即玩），后续微信小游戏 / Steam |
| 单局时长 | 3 环 1 分钟 ～ 9 环 20–40 分钟 |
| 目标用户 | ① 解谜爱好者 ② 传统文化爱好者 ③ 数学 / 编程 /  STEAM 教育场景 |
| 商业模式（可选） | 免费本体 + 材质皮肤 / 扩展关卡包；教育版授权 |
| 竞品差异 | 市面上多为「九连环模拟器」，只还原操作；本作还原的是**认知过程** |

### 三层用户与对应承诺

- **路人**：3 分钟学会规则，5 分钟解开三连环，获得「我懂了」的快感。
- **玩家**：追求三星（零失误最优解），挑战 8/9 环的长局。
- **硬核 / 教育**：盲解模式、双环变体、格雷码图谱、任意状态求解。

## 2. 设计支柱

1. **规则完全透明，没有隐藏机制。**
   玩家失败永远是因为「记不住」或「算错」，而不是因为不知道规则。任何非法操作都要给出**可读的原因**，而不是简单抖动。

2. **每一步都有反馈。**
   341 步不能是 341 次无声点击。每一步至少有三重反馈：环的物理动画、音高、进度可视化。

3. **文化不是贴皮。**
   每一章绑定一条真实史料与一件文物 / 画作，且与关卡机制有隐喻关系（例如「椎破连环」对应「换一种思路」）。

---

## 3. 核心循环

```
观察当前状态
   ↓
判断哪些环可动（合法环高亮 / 自己推）
   ↓
执行（点击 / 拖拽 / 键盘）
   ↓
反馈（动画 + 音 + 步数 + 距解步数）
   ↓
推进 → 完成 → 结算（星级 / 记录 / 解锁史料）
   ↓
下一局（更长、更绕、或目标不同）
```

单局内的微循环约 3–8 秒；一章约 15–40 分钟。

## 4. 玩法系统

### 4.1 基础操作

- **点击环**：合法则动，非法则抖动并解释原因。
- **拖拽**：环沿钗滑动，松手判定落位（更接近实物，移动端主操作）。
- **键盘 1–9**：直接操作对应环；`Z` 撤销；`Esc` 关闭弹层。
- 合法环在悬停 / 触摸时轻微发光；「提示」会高亮下一步。

### 4.2 教学：三环上手

不写长篇说明，用**三个环**做一次完整示范：

1. 第一步只允许点第 1 环（其余高亮为灰），强制走对。
2. 第二步高亮第 3 环，并显示「领头环是第 2 环」的箭头。
3. 第三步开始撤掉引导，只保留「合法环」高亮。
4. 五步解完后，弹出「你刚刚做的事，叫递归」。

> 目标：90 秒内让玩家理解两条规则，且**亲手完成一次完整解环**。

### 4.3 关卡表

以「全上 → 全下」为主轴，逐步加长：

| 关卡 | 环数 | 最优步数 | 状态数 | 作用 |
|---|---|---|---|---|
| 三连环 | 3 | 5 | 8 | 教学 |
| 四连环 | 4 | 10 | 16 | 巩固奇偶规律 |
| 五连环 | 5 | 21 | 32 | 第一次「长局」 |
| 六连环 | 6 | 42 | 64 | 节奏训练 |
| 七连环 | 7 | 85 | 128 | 中途易错点 |
| 八连环 | 8 | 170 | 256 | 耐力 |
| 九连环 | 9 | 341 | 512 | 主线终局 |
| 复原 | 9 | 341 | — | 反向：从散到整 |
| 独环 | 9 | **511** | — | 最难初态（仅第 9 环在钗） |

公式：`a(n) = (2^(n+1) − (n 偶 ? 2 : 1)) / 3`；任意两状态距离 `|d(x) − d(y)|`。

### 4.4 星级

| 星级 | 条件 |
|---|---|
| ★★★ | 步数 = 理论最优（零回头路） |
| ★★ | 步数 ≤ 最优 × 1.3 |
| ★ | 完成 |

对 341 步的关卡，三星意味着「一次都不能错」——这才是真正的挑战，而不是重复劳动。

### 4.5 辅助系统（降低枯燥感的关键）

| 功能 | 说明 |
|---|---|
| 撤销 | 无限次，回退一步 |
| 重置 | 回到本局初态 |
| 提示 | 高亮下一步合法环 + 解释规则 |
| 演示 | 按最优解自动播放，可随时接管 |
| 分段检查点 | 每 40 步弹出一张史料卡，兼作心理休息点 |
| 距解步数 | 实时显示「还需 N 步」，把抽象进度变成数字 |
| 自动存档 | 退出后可从当前状态继续 |

### 4.6 进阶模式（差异化）

1. **盲解**：环的状态被遮住，只能靠计数与记忆。硬核玩家的终极形态。
2. **双环同动**：允许同时移动两端环，最少步数变为 `1,1,4,7,16,31,64,127,256`（OEIS A051049）。
3. **限步**：给定一个略高于最优的步数上限。
4. **逆序**：只允许「上环」，从全散到全整。
5. **无尽 / 每日一题**：随机生成初态与目标态，按 `|d(x)−d(y)|` 给出标准答案与排行榜。

### 4.7 收集与图鉴

- **史料卡**：每章 3–4 张，解锁后可翻阅（原文 + 白话 + 出处）。每 40 步得一张；解局再得一张，三星额外多得一张——短局也能集齐本章。
- **器物皮肤**：黄铜 / 白银 / 翡翠 / 乌木，对应不同解锁条件。
- **格雷码图谱**：一张 512 节点的环形图，玩家走过的状态被点亮成一条路径——把「我走了多远」变成可收藏的图形。

### 4.8 卷二新增 · 数局（数字滑块）

卷二不止「木局」。为了让「搜索」这条主轴同时容纳**状态图搜索**与**启发式搜索**，卷二内新增「数局」，与木局共用卷壳、存档与弹层，不改变四卷格局。

- **盘面**：九宫 3×3、十六宫 4×4（默认）、廿五宫 5×5；`1 … n²−1` 按行排好、空格在右下即胜。
- **操作**：点空格旁的数；或聚焦数字后按方向键（挨着空格即滑入，否则移焦点）；`Enter` / `Space` 直接滑入。
- **生成**：从复原态按固定 seed 倒走 `depth` 步，天然可解、可复现；发布前用逆序数 + 空格行号复核奇偶。
- **提示 / 演示**：曼哈顿距离 + 线性冲突的加权 A*（权重 3）。只称「参考解」，不冒充最优；超节点上限明确失败。
- **胜利**：不给星级，不声称最优；只列步数、用时与历史最佳。
- **存档**：数局会话独立为 `volumes.huarong.sessionDigital`，进度键 `digital-9` / `digital-16` / `digital-25`；`settings.huarongMode` 记忆上次模式。
- **入口**：右栏「木局 / 数局」切换；`?play=huarong&mode=digital` 可深链进入。

> 数局的意义不是「再加一个滑块游戏」，而是让玩家在同一卷里看见两种搜索：木局用 BFS 枚举状态图，数局用 A* 估计「还差多远」。

## 6. 美术方向（已定）

### 6.1 概念：夜案 · 一盏灯下的铜器

不做常见的「米色宣纸 + 宋体」国风，而是把九连环当成**博物馆展柜里唯一的发光物**：深墨底、单点暖光、铜金为唯一亮色，朱砂只做印章级点缀。

- 好处一：黄铜与暖光天然互相成就，器物质感直接拉满。
- 好处二：画面只有一个焦点，341 步也不会视觉疲劳。
- 好处三：与同类「宣纸底」产品形成一眼可辨的差异。

### 6.2 色板

| 名称 | 值 | 用途 |
|---|---|---|
| 夜玄 | `#0f110c` | 底色 |
| 苔墨 | `#232a20` | 次级面 |
| 铜金 | `#c8a05a` | 主强调、器物 |
| 亮金 | `#f2dca6` | 高光、数值 |
| 朱砂 | `#c0432f` | 印章、主按钮 |
| 宣白 | `#e6ddc8` | 正文 |

### 6.3 字体

- 标题 / 关卡名：**楷体**（KaiTi / STKaiti）——带笔锋，有书卷气。
- 正文 / 数据：**宋体**（Songti / SimSun），数字使用 tabular 对齐。
- 全站只用这两族，靠字号与字距区分层级。

### 6.4 构图

```
┌──────┬────────────────────────┬──────────┐
│      │                        │  关卡名   │
│ 解   │                        │  步数/用时 │
│ 连   │      [ 器物 · 灯下 ]     │          │
│ 环   │                        │  两则规则 │
│      │                        │          │
│ 印   │   ●●●●●●●●● · 距解 341  │          │
├──────┴────────────────────────┴──────────┤
│        撤销 重置 提示 演示 关卡 说明        │
└───────────────────────────────────────────┘
```

- 桌面：左竖排题名 + 中器物 + 右铭牌，非对称。
- 移动：题名横置顶部，器物居中，操作条贴底，状态压缩成一行。

### 6.5 动效原则

- **只让动效回答动作**：点击 → 环抬起、越过钗尖、落下，380ms，带轻微旋转。
- 入场只做一次：环自下而上依次亮起，40ms 错峰。
- 非法操作：短促抖动（340ms）+ 文字解释，不弹窗。
- 尊重 `prefers-reduced-motion`。

### 6.6 材质皮肤

| 皮肤 | 主色 | 获取 |
|---|---|---|
| 黄铜（默认） | `#c8a05a` | 初始 |
| 白银 | `#cfd6d2` | 通关红楼 · 七连环 |
| 翡翠 | `#8fbf9f` | 全部九局三星 |
| 乌木 | `#b08a5e` | 通关全部九局 |

器色只替换铜环、钗与金色系 CSS 变量；暖灯、纸纹与朱砂印章保持不变。

## 7. 音频

### 7.1 核心创意：可听的算法

把**环号映射到五声音阶**（宫商角徵羽），每一步的环决定音高，上下环决定音色（上 = 泛音，下 = 实音）。

于是：**一整局 341 步 = 一段固定的旋律**。玩家会在第 50 步左右开始「听出」自己在哪一段，这是任何 UI 都给不了的进度感。

- 音源：Web Audio 合成（正弦 + 三角 + 短噪声），零素材、体积为零。
- 环境音：极轻的纸面摩擦与远处更漏，音量低于 -30dB。
- 静音开关必须存在且易达。

### 7.2 无障碍

- 音高不作为唯一反馈（同时有视觉 + 数字）。
- 提供「高对比」模式。
- 全键盘可操作。

## 9. 技术方案

### 9.1 选型

| 方案 | 结论 |
|---|---|
| **原生 HTML/CSS/JS + SVG（推荐）** | 零依赖、零构建、单文件可运行、`file://` 直接打开、易部署 |
| Canvas 2D | 小游戏移植方便，但文字与矢量质感差 |
| Three.js | 材质最好，但移动端性能与工期风险高 |
| React/Vue | 对单页小游戏属于过度工程 |

> 当前原型即采用方案一，已可运行。

### 9.2 状态模型

用 9 bit 整数表示状态，第 i 环在 `bit(i-1)`：

```js
gray2bin(g)          // 距离：状态 → 最短步数
bin2gray(b)          // 反解
canMove(s, k)        // 合法性，O(1)
nextState(s, goal)   // 沿最优路径走一步
```

- 状态空间 512，**可全量预计算**，任何查询都是 O(1)。
- 任意目标状态关卡可即时生成，最优步数精确可判。

### 9.3 渲染分层

```
barBack   ← 后侧钗股
rings     ← 在钗上的环（被前侧钗股压住，形成「穿过」错觉）
barFront  ← 前侧钗股 + 钗眼
animLayer ← 正在移动的环（临时提到最上层）
```

环用「外轮廓 + 渐变环体 + 内轮廓 + 高光弧」四层同心圆构成，无需贴图即有线材质感。

### 9.4 存档

`localStorage` 单键 JSON：`{ 关卡ID: { best, stars } }`。
长局额外存 `snapshot`（当前状态、步数、用时），用于中途退出续玩。

### 9.5 性能

- 同屏最多 9 个环，DOM 节点 < 100，无需虚拟化。
- 动画用 Web Animations API，合成层完成，不触发布局。
- 目标：低端安卓 60fps；首屏 < 1s。

### 9.6 可移植性

- 逻辑层（状态机 / 求解器）与渲染层分离，可直接复用到小游戏或 Flutter WebView。
- 若做微信小游戏：替换 SVG 为 Canvas 渲染，逻辑层零改动。

### 9.7 发布与离线（M4）

- **单文件本体 + 外挂发布壳**：`index.html` 仍可 `file://` 直开；`manifest.webmanifest`、`sw.js`、`icons/` 只在静态托管下增强安装与离线。
- **Service Worker**：预缓存页面、Manifest、图标与分享底图；导航网络优先（2.5s 超时回退缓存），静态资源缓存优先后台更新。
- **分享卡片**：结算时用 Canvas 现画 1200×630 PNG，支持系统分享、保存图片、复制配文；断网可用。
- **社交元信息**：Open Graph / Twitter Card + 1200×630 底图；正式域名确定后将图片改为绝对地址。
- 详细上线步骤、响应头、更新与回退见 `docs/03-发布与部署.md`。

## 10. 数据与平衡

### 10.1 难度曲线

步数每关约翻倍（5 → 10 → 21 → 42 → 85 → 170 → 341），符合「每关一次指数跳跃」的节奏。建议在 4 环与 7 环之间插入**可选支线**，避免主线过长导致流失。

### 10.2 流失点预判

| 位置 | 风险 | 对策 |
|---|---|---|
| 六连环（42 步） | 第一次遇到 40 步检查点 | 史料卡兼作休息点；可随时演示 |
| 七连环（85 步） | 中途断线 | 自动存档续玩 |
| 九连环（341 步） | 劝退 | 分段史料卡 + 音乐段落感 + 允许演示 |
| 独环（511 步） | 极硬核 | 定位为挑战关，不计入主线 |
